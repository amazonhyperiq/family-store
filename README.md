# Amazon HR & Finance — Foundation

واجهة تأسيسية مستقلة لنظام الموارد البشرية والمالية. هذه النسخة هي نقطة انطلاق تطويرية وليست نظاماً إنتاجياً ولا تتصل بعد بقاعدة Nhost.

## المبادئ
- إبقاء النظام القديم كما هو حتى اجتياز الترحيل والاختبارات والموافقة على التحويل.
- لا تُستخدم بيانات حقيقية أو كلمات مرور حقيقية في بيئة التطوير.
- صلاحيات الخادم هي مصدر القرار؛ إخفاء عناصر الواجهة ليس حماية.
- لا تُخزّن كلمات المرور كنص صريح ولا يمكن للمدير أو المانح استرجاع كلمة المرور الحالية. المسموح هو تغييرها أو إعادة تعيينها.
- البصمة/Face ID لا تُخزّن داخل الموقع؛ عند اعتمادها تُنفّذ عبر Passkeys/WebAuthn بعد التحقق من دعم المنصة.

## التشغيل المحلي
1. ثبّت Node.js LTS.
2. فك الضغط وافتح المجلد في الطرفية.
3. نفّذ `npm install`.
4. انسخ `.env.example` إلى `.env` وأدخل القيم العامة الخاصة بمشروع Nhost بعد تأكيد المشروع الصحيح.
5. نفّذ `npm run dev`.

## بنية المشروع
- `src/`: واجهة React + TypeScript RTL.
- `database/migrations/`: مخطط PostgreSQL الأولي.
- `nhost/functions/`: مكان وظائف الخادم، ومنها إرسال الإشعارات.
- `public/`: ملفات عامة مثل Service Worker لاحقاً.

## وحدات النظام المستهدفة
الموظفون، العقود والتكليفات، الرواتب، السلف والتسديدات، المانحون، الاستقطاعات، المكافآت، الحضور، العمل الإضافي، الإجازات، الإشعارات، الصلاحيات، التدقيق والتقارير.

## قواعد مالية مثبتة من متطلبات المشروع
- العمل الإضافي يُسعّر بمعدل يحدده المدير لكل موظف/تكليف؛ لا يوجد معامل مضاعف تلقائي.
- العمل الثاني مستقل عن العمل الأساسي وله كشف واستحقاق منفصل.
- الراتب المتفق عليه بالدولار يبقى بالدولار، والعمل الإضافي بالدينار العراقي.
- كل عملية مالية تحفظ العملة والتاريخ والمنفذ والمرجع وسجل التدقيق.

## قبل الإنتاج
- اعتماد مخطط البيانات النهائي بعد مطابقة متطلبات العمل.
- إعداد Nhost Auth وHasura permissions لكل دور.
- إعداد اختبارات صلاحيات تمنع المانح من الوصول إلى بيانات مانح آخر.
- إعداد مفاتيح Push في أسرار الخادم فقط.
- استيراد نسخة تجريبية من البيانات ومطابقة الأرصدة.
- اختبار الاسترجاع والنسخ الاحتياطي.
- عدم تحويل المستخدمين إلى النظام الجديد قبل موافقة صريحة.
